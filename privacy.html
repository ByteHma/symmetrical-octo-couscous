Privacy Policy

How the personal Google Drive backup connector handles Google user data.

Effective: October 14, 2026 · Operator: ByteHma

1. Purpose and audience

This OAuth application is used for personal, owner-operated backups between a local workstation and the owner's Google Drive account through rclone. It is not a public cloud backup service, does not provide accounts to visitors, and does not offer a web-based Google sign-in.

2. Google user data accessed

The connection requests the Google Drive drive.file scope. This permits access to Drive files created by the application or otherwise explicitly made available to it, including relevant file contents, file names, identifiers, sizes, timestamps, and other metadata needed for transfers and verification. It does not request unrestricted access to all Google Drive files.

3. How data is used

Data is used solely to create or update authorized backup files, list and verify those files, download them for restoration, and report transfer or integrity errors to the account owner. Data is not used for advertising, profiling, resale, model training, or unrelated purposes.

4. Storage and security

Backup files are stored in the owner's Google Drive account at the owner's direction. The documented Development Friction Knowledge Base (DFKB) backup workflow encrypts its archive locally before transfer. Encryption must be separately configured and verified for any additional backup workflow; merely using the OAuth connector does not encrypt all data automatically.

OAuth tokens and local configuration belong on the owner's workstation and are not embedded in this website or committed to this public repository. Local tools and Google Drive handle the relevant file transfers; the GitHub Pages website does not receive tokens or backup contents.

5. Sharing and disclosure

The operator does not sell or voluntarily disclose Google user data to advertisers, data brokers, or unrelated third parties. Files are transmitted to and stored by Google Drive to provide the storage the owner requested; Google's service terms and privacy practices apply. The operator does not independently transmit backup content to GitHub Pages. Disclosure may occur only if required by applicable law or explicitly directed by the owner.

6. Website visitors

This website is a static GitHub Pages publication with no application-operated cookies, tracking scripts, analytics, forms, or account registration. GitHub may process access logs and technical information when serving the site under its own privacy statement.

7. Retention and deletion

Backup files remain in the owner's Drive until the owner deletes them or the storage provider applies its retention rules. The owner controls local credentials and backup copies. Revoking OAuth authorization prevents further authorized API access but does not automatically delete previously stored backups. The owner can remove those separately.

8. Access control and revocation

The owner can review or revoke the connection through Google Account connections. The owner may also delete local rclone credentials and stored backup files. Revoking access may interrupt backup and restore operations until the connector is reauthorized.

9. Google API data-use restrictions

Google user data obtained through Google APIs is used only for the backup functions described above. The operator does not transfer that data to unrelated services or use it for secondary purposes. Any material change to the requested permissions or data-handling practices requires an updated disclosure.

10. Contact and changes

For questions about this personal project, contact its maintainer through the ByteHma GitHub profile. Do not post credentials or private backup contents in public repository discussions. This policy may change if the personal workflow changes; the effective date will be updated.
